# 📸 게시물 탭 (팔로플래너 "게시물" 탭)

사진 1~10장과 주제 한 줄로 **인스타그램 · 구글 소식 · 네이버 소식 · 당근 소식** 4개 채널 문구를 한 번에 만들고,
인스타·구글은 즉시/예약 자동 게시, 네이버·당근은 복사·사진 받기로 올리는 탭.
2026-10-24 맥미니 세션에서 설계(brainstorming). 구현은 아래 "만드는 순서"대로 단계별로.

관련 문서: 블로그 작성기 `docs/blog-writer/README.md`(지점 표·공통 규칙), 메타 마케팅 `~/pallo-planner-marketing/docs/meta-marketing/README.md`(브랜치 `feat/meta-marketing`).

## 확정된 결정 (사용자와 정함)

- **독립 탭.** 블로그 탭 서브탭이나 마케팅 탭 안이 아니라 새 탭 `post.js` / `post.css` (`window.PS`). sales.js·blog.js 와 같은 방식으로 index.html 전역(sb·me·esc·toast…)을 쓴다.
- **채널별 게시 방식:**
  | 채널 | 방식 | 이유 |
  |---|---|---|
  | 인스타그램 | 공식 API 자동 (즉시·예약) | Instagram Graph API 콘텐츠 게시 |
  | 구글 비즈니스 프로필 소식 | 공식 API 자동 (즉시·예약) | Business Profile API `localPosts` (사용 신청·승인 필요) |
  | 네이버 스마트플레이스 소식 | 반자동: [📋 복사] + [🖼 사진 받기] + 앱 열기 → [올렸어요] | 공식 API 없음 |
  | 당근 비즈프로필 소식 | 반자동 (네이버와 같음) | 공식 API 없음 |
- **네이버·당근 브라우저 자동화(맥미니 Playwright)는 1차에서 안 함.** 반자동으로 운영해 보고 나중에 실험(화면 변경에 약하고, 비공식이라 계정 제재 가능성).
- **1차 범위 = 사진 게시물만** (1장 또는 2~10장 캐러셀) + 문구. **릴스(영상)는 메타 마케팅 ④영상 단계에서 이 탭의 게시 엔진을 재사용.**
- **마케팅 탭과의 관계:** 마케팅 설계의 "②콘텐츠 시안 → 매니저 승인 → ⑤예약 자동 게시" 중 **게시 부분을 이 탭이 맡는다.** 마케팅 스킬은 나중에 시안을 `sns_posts` 에 넣기만 하면 된다.
- **권한:** 블로그와 같음. 매니저 = 자기 지점만, 대표(role=admin) = 전 지점 + 설정 탭 + 사용량.

## 화면

서브탭 3개: **만들기 · 목록 · 설정**(설정은 대표만).

### 만들기
1. **사진 1~10장** → 블로그 탭과 같은 얼굴 자동 모자이크·직접 모자이크·자르기·밝기·순서 바꾸기. 인스타용 1:1 / 4:5 자르기를 기본 제안.
2. **주제 한 줄**(선택). 비우면 사진만 보고 씀. 블로그 탭 [게시물로 보내기]로 들어오면 블로그 제목·본문이 주제 칸에 들어옴.
3. **어투** 1개만 고름: 친근 / 정중. 나머지(지점명·위치·상담 방법·강점)는 지점 프로필(`blog_profiles`)에서.
4. **[✨ 문구 만들기]** → AI가 공통 원고 1개 + 채널 4개 버전. 채널별 탭에서 보고 직접 고칠 수 있음.
5. **발행 전 점검기**(블로그 것 재사용): 컬컴/CULCOM 언급, 과장 표현(학원법), 가격 표기, 얼굴 확인 안 한 사진 → **경고만**, 막지 않음.
6. **보낼 채널 체크** →
   - 인스타·구글: [지금 게시] 또는 [예약](날짜·시간). 그 지점에 계정 연결이 안 돼 있으면 체크 칸이 꺼지고 "대표님이 설정에서 연결" 안내.
   - 네이버·당근: [📋 문구 복사] [🖼 사진 번호대로 받기] [앱/사이트 열기] → 올린 뒤 [올렸어요].

### 목록
내 지점 게시물 최신순 카드. 카드마다 채널 4개 뱃지:
`예약됨 10/27 19:00` · `게시됨 ↗`(링크) · `실패 — 이유 [다시 시도] [직접 올리기]` · `복사 대기` · `올렸어요`.
대표는 지점 고르기 + 전체. 이 목록(최근 20건 주제·제목)을 AI에 넘겨 주제 중복을 피한다.

### 설정 (대표)
- 지점마다 인스타 비즈니스 계정 ID, 구글 위치 ID 연결 + [연결 확인] 버튼(상태: 정상 / 토큰 문제 / 권한 없음).
- 지점당 하루 AI 생성 제한: 블로그 사용량 탭의 제한(`blog_limits`)을 같이 씀 — **블로그 글·변환·스타일·게시물 문구를 합쳐서** 하루 N회(기본 10, 대표가 조정).

## 채널별 변형 규칙 (prompt 에 들어갈 내용)

| 채널 | 형식 | 톤·내용 | 제한 |
|---|---|---|---|
| 인스타 | 첫 줄 훅 → 본문(줄바꿈 많이) → 해시태그 15~20개 | 블로그 해시태그 순서 규칙(넓은 → 핵심 → 롱테일 → 브랜드). 이모지 적당히 | 캡션 2,200자, 해시태그 30개, 캐러셀 2~10장, 비율 4:5~1.91:1, JPEG |
| 구글 소식 | 본문 + 버튼(전화 / 예약 / 자세히) | "지점명·동네·과목"을 자연스럽게 포함, 존댓말, 해시태그 없음. 유형: 일반 / 이벤트(기간) / 혜택(기간) | 본문 1,500자, 사진 1장(첫 장, 긴 변 720px 이상, 5MB 이하) |
| 네이버 소식 | 제목 + 본문 | 플레이스에 들어온 사람 대상 → 수업 안내·이벤트·이번 달 일정 등 "지금 상담할 이유". 해시태그 없음 | 제목 20자 안팎. 본문 글자 수·사진 수 제한은 **구현 때 스마트플레이스 화면에서 확인해 이 표에 기록** |
| 당근 소식 | 제목 + 본문 | 동네 이웃 말투(친근한 존댓말), 동네명 앞세움(옥계동·삼산동·동성로), 동네 혜택 1개, 과장 금지 | **구현 때 당근 비즈프로필 화면에서 확인해 기록** |

**공통 절대 규칙(블로그와 동일):** 컬컴/CULCOM 언급 금지 · 후기·숫자 지어내지 않기(`[확인 필요]` 표시) · 주소·상담 방법은 지점 프로필 값만 · 학원법 과장 표현 경고.

**지점 간 유사도:** 같은 틀로 지점명만 바꾼 글은 네이버 스팸 정의에 해당 → **네이버 소식만** 다른 지점 최근 네이버 소식과 유사도 검사(blog-write `similar` 재사용). 인스타·구글·당근은 검사 안 함.

## 데이터 (마이그레이션 1개)

- **`sns_accounts`** — 지점(team_id) × 채널(`instagram` | `google`): 외부 ID(인스타 비즈니스 계정 ID / 구글 `accounts/…/locations/…`), 표시 이름, 상태(`ok` | `token` | `perm` | `unknown`), 확인 시각. **토큰은 여기 두지 않는다.**
- **`sns_posts`** — 게시물 1건: team_id, 작성자, 주제, 어투, 공통 원고, 사진 목록(순서·Storage 경로·가로세로), 채널별 문구 JSON(`instagram{caption,hashtags}` / `google{body,type,button,start,end}` / `naver{title,body}` / `daangn{title,body}`), 출처(`direct` | `blog:<id>` | `marketing:<id>`), 만든 시각.
- **`sns_jobs`** — 게시물 × 채널 1건: 방식(`api` | `manual`), 예약 시각(즉시면 지금), 상태(`queued` · `running` · `posted` · `failed` · `waiting_copy` · `done_manual`), 결과 URL·외부 ID, 오류(원문 + 한국어 풀이), 시도 횟수, 다음 시도 시각. 목록 뱃지는 전부 여기서.
- **Storage `sns` 버킷(공개)** — 인스타·구글 API가 사진을 **공개 https 주소**로 가져가야 함. `blog-temp` 와 같은 패턴: JPEG만, 무작위 파일 이름, 자기 지점 폴더(`<team_id>/…`)에만 올리기, 대표는 전부. 모자이크·자르기는 기기 안에서 끝낸 뒤 올리므로 원본 얼굴 사진은 서버에 올라가지 않는다. 예약 대기 중엔 지우면 안 되므로 **모든 작업이 끝난(게시됨·실패·올렸어요) 뒤 7일 지나면** tick 에서 삭제.
- **재사용:** AI 생성 횟수·비용은 `blog_gens` 에 kind=`sns` 로 기록 → 블로그 사용량 탭에 같이 보임. 하루 제한은 `blog_limits` 공용(`blog-write` 의 `AI_KINDS` 에 `sns` 추가 → 블로그와 합산). 지점 정보는 `blog_profiles`.
- **RLS:** `blog_my_team()` / `blog_is_admin()` 재사용. 매니저는 자기 지점 행만 읽기·쓰기, `sns_accounts` 쓰기는 대표만. `sns_jobs` 의 상태를 `posted` 로 바꾸는 건 Edge Function(서비스 키)만 — 매니저는 `waiting_copy → done_manual` 만 가능.
- **실시간:** `sns_jobs` 변경 구독 → 예약 게시가 끝나면 열린 화면 뱃지가 바로 바뀜(기존 탭들과 같은 방식).

## 게시 엔진 (Edge Function `sns-publish`)

| action | 누가 | 하는 일 |
|---|---|---|
| `publish(job_id)` | 매니저 [지금 게시]·[다시 시도] | 호출자 지점 = 작업 지점 확인 → 채널별 게시 → `sns_jobs` 갱신 |
| `tick` | pg_cron 1분마다 (서비스 키는 DB 설정값에만) | 예약 시각 지난 `queued` 작업을 `running` 으로 **먼저 잠그고**(중복 실행 방지) 게시. 한 번에 최대 3건(실행 시간 150초 제한), 나머지는 다음 분. 끝난 지 7일 지난 사진 정리 |
| `check(team, channel)` | 대표 [연결 확인] | 인스타 계정 정보 조회 / 구글 위치 조회로 토큰·권한 확인 → `sns_accounts.status` |

**인스타 게시 순서(메타 공식 흐름):** 1장 = 이미지 컨테이너(공개 URL·캡션) → 게시. 캐러셀 = 사진마다 자식 컨테이너 → 캐러셀 컨테이너(캡션) → 상태 `FINISHED` 될 때까지 몇 초 간격 확인 → 게시 → 퍼머링크 저장. 계정당 하루 API 게시 제한은 우리 사용량(지점당 주 3~5건)과 무관.

**구글 소식:** 리프레시 토큰 → 액세스 토큰 → 위치에 `localPosts` 생성(본문·유형·버튼·사진 URL 1장, 이벤트·혜택이면 기간).

**실패 처리:**
- 일시 오류(네트워크, 메타·구글 5xx, 컨테이너 처리 중) → 5분 간격 최대 3번 재시도 후 `failed`.
- 영구 오류(토큰 만료, 권한 없음, 사진 규격 거부) → 바로 `failed` + 한국어 이유 + 매니저 푸시(기존 푸시 알림). 토큰·권한 문제면 대표에게도, `sns_accounts.status` 갱신.
- 실패 카드엔 [다시 시도]와 [직접 올리기(복사·사진 받기)] 둘 다 → 자동이 막혀도 그날 게시는 놓치지 않는다.

**글쓰기 AI:** 기존 `blog-write` 함수에 `sns` action 추가. 입력 = 사진(축소본) + 주제 + 지점 프로필 + 어투 + 최근 게시물 20건 주제 → 출력 = 공통 원고 + 채널 4개 JSON. 모델·깊이(low 기본)·비용 기록은 블로그와 같다. 하루 제한 초과 시 블로그와 같은 안내.

**비밀값(Supabase secrets, 채팅에 붙이지 않기):** `META_SYSTEM_USER_TOKEN`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REFRESH_TOKEN`, pg_cron 이 쓰는 함수 호출 키는 DB 설정값(vault).

## 대표가 준비할 것

- **메타:** 마케팅 문서의 "메타 API 준비" 1~5 그대로(비즈니스 인증 → 비즈니스 앱 → 시스템 사용자 → 4개 지점 자산 할당 → 토큰). 이 탭에 꼭 필요한 권한: `instagram_basic`, `instagram_content_publish`, `pages_show_list`, `pages_read_engagement`, `business_management`. 우리 소유 계정에만 올리므로 앱 리뷰 없이 됨. **인스타 4개 계정이 프로페셔널(비즈니스) 계정이고 각 지점 페이스북 페이지에 연결돼 있어야 함.**
- **구글:** 4개 지점 비즈니스 프로필을 한 구글 계정이 관리하는지 확인 → Google Cloud 프로젝트 → Business Profile API 사용 신청(양식, 며칠~2주) → 승인 뒤 맥미니에서 1회 로그인해 리프레시 토큰을 secret 으로.
- **네이버·당근:** 각 매니저 폰에 스마트플레이스·당근 비즈니스 앱 로그인.

## 만드는 순서

| 단계 | 내용 | 끝나면 | 외부 승인 필요 |
|---|---|---|---|
| 0 | 마이그레이션(테이블 3개·버킷·RLS), 탭 뼈대·서브탭, blog.js 사진 처리(모자이크·자르기·사진 받기)를 공용 모듈 `photo.js` 로 분리 → 블로그 탭이 그대로 동작하는지 확인 | 빈 탭 | 아니요 |
| 1 | 만들기: AI 문구 4채널(`blog-write` `sns` action) + 점검기 + 네 채널 모두 복사·사진 받기 + 목록 | **이것만으로 바로 운영 가능** | 아니요 |
| 2 | `sns-publish` 인스타 즉시·예약 게시, pg_cron tick, 목록 뱃지·실시간, 실패 처리·푸시, 설정 탭(인스타) | 인스타 자동 | 메타 토큰 |
| 3 | 구글 소식 API + 설정 탭(구글) | 구글 자동 | 구글 API 승인 |
| 4 | 블로그 탭 [게시물로 보내기], 마케팅 시안 → `sns_posts` 연결, 7일 뒤 사진 정리 | 연결 완료 | 아니요 |

메타·구글 준비가 늦으면 1단계로 먼저 운영한다. 각 단계는 실제로 쓰면서 확인한 뒤 다음으로.

## 검증

- **로컬:** 맥미니 `~/.cache/pallo-planner-dev` 로컬 Supabase + launch.json `planner-local`(8766). AI·메타·구글 응답은 가짜 응답 하네스로 먼저 화면 검증(블로그 때 `~/pallo-blog-harness` 방식).
- **0단계:** 사진 처리 분리 후 블로그 탭 회귀 확인(모자이크·자르기·사진 받기·네이버 붙여넣기).
- **인스타 실게시 첫 테스트는 구미점 계정**(오픈 전·노출 0) → ① 1장 ② 캐러셀 3장 ③ 2분 뒤 예약 ④ 틀린 토큰으로 실패 표시·푸시. 확인 후 게시물 삭제.
