## 리드가 있는 곳: 신규 회신 `/{코드}/admin/call`

- "신규 회신 통합 관리" — 신규 지원자의 콜백부터 상담 예약 확정까지. 탭: 캘린더 / 예약 히스토리 / **데이터 보드**.
- 데이터 보드 아래 목록 표 (페이지당 20명, 지원 시간 최신순). 열:
  `누적 콜수 | 상태 | NAME | 코멘트 | 전화번호 | 유입경로 | 광고 매체 | 광고명 | 지원 시간 | 마지막 업무 시간 | 삭제`
  - 읽는 열: **상태, 유입경로, 광고 매체, 광고명, 지원 시간**. NAME·전화번호·코멘트는 읽지 않는다.
  - 광고명이 `-` 이면 광고가 아닌 경로(랜딩페이지·네이버 예약 등) → ad_name 빈칸.
- 상태 필터 (select): `전체(ALL) / 진행중 (신규·진행중)(active) / 전화상 안함(NO_CALL) / 최후 통첩(ULTIMATUM) / 예약확정(RESERVED)`. 스니펫이 "전체"로 바꾼다.
- 페이지 넘김: 표 밖의 숫자 버튼 `1 2 3 … 10`. 위쪽 `‹ ›` 는 데이터 보드의 '이전 달/다음 달' 이라 쓰면 안 된다.
- 상세 창(행 클릭): 동기/유입 경로(`외부 유입 · 인스타그램 · 광고 · {광고명}`), 지원 시간, 누적 콜수, **이미 등록된 회원 n명**(같은 이름·전화번호 회원 수 — 전산이 자동 매칭), 결과 입력(전화상 안함 / 최후통첩).

## 상태값 → 표준값 (mk-core `STATUS_MAP`, 띄어쓰기 무시)

| 전산 | 표준 | 비고 |
|---|---|---|
| 진행 중 | lead | 신규·콜백 중 |
| 최후 통첩 | lead | 마지막 연락 시도 |
| 예약 확정 | consult | 상담(첫 방문) 예약 확정 |
| 전화상 안함 | lost | 번호 오류·연락 안 됨 |
| (상세 창 '이미 등록된 회원' ≥ 1) | enroll | 스니펫이 상태를 "등록"으로 바꿔 넘긴다 |

- 방문(visit)은 신규 회신에 따로 없다 → 현재는 consult 다음이 enroll. 
- **주의:** '이미 등록된 회원'은 이름·전화번호가 같은 회원이 있으면 1 — 원래 회원이 다시 지원해도 등록으로 잡힌다. 리포트 페르소나 caution 에 적는다.
- 신규 등록(`/admin/register`)은 회원 입력 양식, 멤버(`/admin/members`)는 카드 목록이라 광고명이 없다 → 광고별 등록은 위 상세 창으로만 알 수 있다.

## source_key

전산 목록에 행 ID 가 보이지 않아서 `지원시각(분)|광고명|같은분·같은광고 순번` 으로 만든다 (예: `2026-10-24T19:35|261012 대구영어광고|0`). 개인정보 없음. 상태가 바뀌어도 키는 그대로라 upsert 로 갱신된다.

## 읽는 방법

`scripts/mk/jeonsan-extract.js` 를 Claude in Chrome `javascript_tool` 로 신규 회신 페이지에 넣는다. 한 번 실행이 45초에서 끊기므로 백그라운드로 돌리고 `window.__mkLast` 를 확인한다. 한 명당 약 1.3초 (상세 창 확인) — 5주치 지점당 약 300명 ≈ 7분.
2026-10-24 시험: 동성로 10/20~24 → 59명 3페이지, 진행 중 24 · 예약 확정 17 · 전화상 안함 16 · 등록 2, 광고명 없음 11.

API(`api.pallo.co.kr/backoffice/api/v1/{코드}/admin/candidates`)는 로그인 토큰이 필요해 쓰지 않는다 (토큰을 꺼내지 않는다). 전산 개발자가 읽기 전용 내보내기를 주면 이 문서와 스니펫을 바꾼다.
