## 리드가 있는 곳: 신규 회신 `/{코드}/admin/call`

- "신규 회신 통합 관리" — 신규 지원자의 콜백부터 상담 예약 확정까지. 탭: 캘린더 / 예약 히스토리 / **데이터 보드**.
- 데이터 보드 아래 목록 표 (페이지당 20명, 지원 시간 최신순). 열:
  `누적 콜수 | 상태 | NAME | 코멘트 | 전화번호 | 유입경로 | 광고 매체 | 광고명 | 지원 시간 | 마지막 업무 시간 | 삭제`
  - 읽는 열: **상태, 유입경로, 광고 매체, 광고명, 지원 시간**. NAME·전화번호는 읽지 않는다. 코멘트는 주간 스니펫이 읽지 않고, 일일 건수 스니펫(아래)만 `gads_`/`nad_`/`homepage` 토큰을 찾으려고 읽는다 — 코멘트 전문은 저장도 반환도 하지 않는다.
  - 광고명이 `-` 이면 광고가 아닌 경로(랜딩페이지·네이버 예약 등) → ad_name 빈칸.
- 상태 필터 (select): `전체(ALL) / 진행중 (신규·진행중)(active) / 전화상 안함(NO_CALL) / 최후 통첩(ULTIMATUM) / 예약확정(RESERVED)`. 스니펫이 "전체"로 바꾼다.
- 페이지 넘김: 표 밖의 숫자 버튼 `1 2 3 … 10`. 위쪽 `‹ ›` 는 데이터 보드의 '이전 달/다음 달' 이라 쓰면 안 된다.
- 상세 창(행 클릭): 동기/유입 경로(`외부 유입 · 인스타그램 · 광고 · {광고명}`), 지원 시간, 누적 콜수, **이미 등록된 회원 n명**(같은 이름·전화번호 회원 수 — 전산이 자동 매칭), 결과 입력(전화상 안함 / 최후통첩).

## 상태값 → 표준값 (mk-core `STATUS_MAP`, 띄어쓰기 무시)

| 전산 | 표준 | 비고 |
|---|---|---|
| 진행 중 | lead | 신규·콜백 중 |
| 최후 통첩 | lead | 마지막 연락 시도 |
| 예약 확정 | consult | 상담(첫 방문) 예약 확정 |
| 전화상 안함 | lost | 번호 오류·연락 안 됨 |
| (상세 창 '이미 등록된 회원' ≥ 1) | enroll | 스니펫이 상태를 "등록"으로 바꿔 넘긴다 |

- 방문(visit)은 신규 회신에 따로 없다 → 현재는 consult 다음이 enroll. 
- **주의:** '이미 등록된 회원'은 이름·전화번호가 같은 회원이 있으면 1 — 원래 회원이 다시 지원해도 등록으로 잡힌다. 리포트 페르소나 caution 에 적는다.
- 신규 등록(`/admin/register`)은 회원 입력 양식, 멤버(`/admin/members`)는 카드 목록이라 광고명이 없다 → 광고별 등록은 위 상세 창으로만 알 수 있다.

## 일일 건수 스니펫 (일일 현황)
- `scripts/mkd/jeonsan-daily.js` 의 `__mkdDaily("YYYY-MM-DD")` — 같은 데이터 보드에서 그 날 유입경로별 **문의 건수만** 센다(상세 창 안 염, NAME·전화번호 안 읽음). 코멘트는 `gads_`/`nad_`/`homepage` 토큰만 찾고 전문은 버린다. 밖으로 나가는 건 숫자와 토큰·유입경로 글자 일부뿐. 날짜 형식이 틀리면 던지지 않고 `{ error }` 를 돌려준다.
- **사전 조건**: 데이터 보드가 **1페이지**이고 날짜 D 가 든 달이어야 한다. D 가 지난달이면 데이터 보드 위쪽 `‹` 를 먼저 한 번 눌러 달을 바꾼다(스니펫은 `‹ ›` 를 누르지 않고 아래 숫자 버튼만 누른다). 같은 탭에서 다시 돌리기 전엔 새로고침(또는 1 클릭) — 스니펫은 마지막으로 본 쪽에 멈춰 있다.

### 실제 화면 확인 (2026-10-29)
대구동성로점 데이터 보드에서 D=2026-10-28 로 돌려 본 결과(당시 기본값 `backDays` 14).
- 표 머리글: `누적 콜수, 상태, NAME, 코멘트, 전화번호, 유입경로, 광고 매체, 광고명, 지원 시간, 마지막 업무 시간, 삭제`. 지원 시간·마지막 업무 시간 모두 `YYYY.MM.DD HH:MM`.
- 상태 select 선택지: `전체`(value `ALL`), `진행중 (신규·진행중)`, `전화상 안함`, `최후 통첩`, `예약확정`.
- 페이지 넘김: 표 밖의 숫자 `<button>`(aria-label 없음). 10쪽까지 넘어갔고 `stoppedBy` `cutoff`, `unparsed` 0, `filterSet` true.
- 결과: `total` 11(meta 9 · 카카오채널 1 · 네이버 예약 1), `scanned` 193, `newest` 2026-10-29, `oldest` 2026-10-13.
- `statuses`(193행): 예약 확정 68 · 전화상 안함 86 · 진행 중 6 · 최후 통첩 33. **"등록" 은 표에 한 번도 나오지 않는다**(주간 스니펫은 상세 창의 '이미 등록된 회원' 으로 등록을 만든다).
- 결정(2026-10-29, 대표): 일일 현황은 **문의만** 보여 준다. 등록은 나중 단계(3단계)에서 다른 전산 화면으로 가져온다.

### 세는 규칙
- 문의 = 지원 시간이 D 인 행. **등록은 세지 않는다** — 등록은 이 표에 없다 → 일일 현황은 문의만, 등록은 나중 단계.
- 표가 지원 시간 최신순이라 D 의 행을 지난 뒤 D-1 보다 오래된 첫 행(`backDays` 기본 1)에서 멈춘다. 쪽 수 상한 `maxPages` 기본 25.
- `bySource` 키(= `mkd_daily(jeonsan)` 의 unit) 순서: ① 코멘트의 토큰(소문자) — `gads_*`=구글, `nad_*`=네이버, `homepage`. 40자까지, 숫자 3자리 이상 덩어리(전화번호 등)가 있으면 그 앞까지만 쓰고(끝의 `_` 는 뗀다) `gads_`/`nad_` 뒤에 남는 글자가 없으면 `기타`. 이 스니펫이 **유일한 방어선**이다 — `rows.mjs` 는 `gads_기타` 같은 값도 받아 주고, `channelOfSource`(mkd-core) 는 `gads_` 로 시작하면 구글로 세기 때문에 `gads_기타` 가 아니라 `기타` 로 돌려준다. ② 광고명이 있고 `-` 가 아니면 `meta`(메타 리드폼). ③ 유입경로 글자 — 숫자 덩어리를 전부 `#` 로 가린 뒤 20자까지(`네이버 예약 0101234567` → `네이버 예약 #`). 비었거나 `-` 거나 결과가 `전체` 면 `기타`.
- `bySource` 와 `statuses` 는 프로토타입 없는 객체(`Object.create(null)`)라 유입경로가 `constructor` 같은 글자여도 그대로 키로 센다.

### 돌려주는 키

| 키 | 뜻 |
|---|---|
| `total` | D 의 문의 합 |
| `bySource` | `{ 키: { inquiries } }` |
| `pages` | 훑은 쪽 수 |
| `scanned` | 지원 시간을 읽은 행 수(멈추게 한 오래된 행 포함) |
| `stoppedBy` | 끝난 이유. `cutoff` = D-1 보다 오래된 행에 닿음(정상) · `lastPage` = 다음 숫자 버튼이 없음(정상) · `maxPages` = 쪽 수 상한(기본 25)에서 멈춤(불완전) · `stalled` = 버튼을 눌렀는데 5초 넘게 표가 안 바뀜(불완전, 같은 쪽을 다시 세지 않음) |
| `newest`, `oldest` | 읽은 첫 행·마지막 행의 지원 시간 날짜(YYYY-MM-DD) |
| `unparsed` | 표에 있는데 지원 시간 날짜를 못 읽은 행 수 |
| `missingCols` | 없는 열 — `코멘트`·`광고명`·`유입경로` 중 |
| `filterSet` | 상태 select 를 찾아 "전체"로 맞췄는지 |
| `statuses` | `{ 상태 글자: 행 수 }` — 읽은 모든 행. 숫자는 `#`, 12자까지. 표에 어떤 상태가 나오는지 보는 용도(화면이 바뀌면 여기서 드러난다) |
| `lastPageRows` | 마지막으로 훑은 쪽의 행 수. `lastPage` 인데 `pages` 가 1이고 이 값이 20 이상이면 꽉 찬 쪽에서 다음 버튼을 못 찾은 것 |

- 오류 반환: 지원 시간 날짜를 하나도 못 읽으면(행은 있는데 `scanned` 0) `{ error: "지원 시간 형식을 못 읽었어요", … }`. 표에 "데이터 없음" 같은 안내 한 줄짜리 행만 있어도 이 오류가 나온다 — 빈 보드는 0건이 아니라 실패로 알린다. 상태·지원 시간 열이 없으면 `{ error: "열 없음: …", headers }`(NAME·전화 열 이름은 뺀다).
- **호출한 쪽의 합격 검사**(스킬): `error` 없음 · `filterSet === true` · `scanned > 0` · `unparsed === 0` · `stoppedBy` 가 `"cutoff"` 또는 `"lastPage"` (단 `stoppedBy === "lastPage" && pages === 1 && lastPageRows >= 20` 이면 꽉 찬 쪽인데 페이지 버튼을 못 찾은 것 — partial) · `newest >= D-14일` (표가 D 가 든 달의 1쪽에서 시작) · `stoppedBy === "lastPage"` 이면 `oldest <= D`. 하나라도 어긋나면 그 지점은 partial/failed.
- 어긋났을 때: `error` 거나 읽은 행이 없으면 `failed`, 그 밖에는 `partial`(숫자를 "적어도 이만큼"으로만 쓴다). `missingCols` 에 코멘트·광고명·유입경로가 있으면 소스 구분이 뭉개지니 `partial`.
