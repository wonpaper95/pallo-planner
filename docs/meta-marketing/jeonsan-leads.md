## 리드가 있는 곳: 신규 회신 `/{코드}/admin/call`

- "신규 회신 통합 관리" — 신규 지원자의 콜백부터 상담 예약 확정까지. 탭: 캘린더 / 예약 히스토리 / **데이터 보드**.
- 데이터 보드 아래 목록 표 (페이지당 20명, 지원 시간 최신순). 열:
  `누적 콜수 | 상태 | NAME | 코멘트 | 전화번호 | 유입경로 | 광고 매체 | 광고명 | 지원 시간 | 마지막 업무 시간 | 삭제`
  - 읽는 열: **상태, 유입경로, 광고 매체, 광고명, 지원 시간**. NAME·전화번호는 읽지 않는다. 코멘트는 주간 스니펫이 읽지 않고, 일일 건수 스니펫(아래)만 `gads_`/`nad_`/`homepage` 토큰을 찾으려고 읽는다 — 코멘트 전문은 저장도 반환도 하지 않는다.
  - 광고명이 `-` 이면 광고가 아닌 경로(랜딩페이지·네이버 예약 등) → ad_name 빈칸.
- 상태 필터 (select): `전체(ALL) / 진행중 (신규·진행중)(active) / 전화상 안함(NO_CALL) / 최후 통첩(ULTIMATUM) / 예약확정(RESERVED)`. 스니펫이 "전체"로 바꾼다.
- 페이지 넘김: 표 밖의 숫자 버튼 `1 2 3 … 10`. 위쪽 `‹ ›` 는 데이터 보드의 '이전 달/다음 달' 이라 쓰면 안 된다.
- 상세 창(행 클릭): 동기/유입 경로(`외부 유입 · 인스타그램 · 광고 · {광고명}`), 지원 시간, 누적 콜수, **이미 등록된 회원 n명**(같은 이름·전화번호 회원 수 — 전산이 자동 매칭), 결과 입력(전화상 안함 / 최후통첩).

## 상태값 → 표준값 (mk-core `STATUS_MAP`, 띄어쓰기 무시)

| 전산 | 표준 | 비고 |
|---|---|---|
| 진행 중 | lead | 신규·콜백 중 |
| 최후 통첩 | lead | 마지막 연락 시도 |
| 예약 확정 | consult | 상담(첫 방문) 예약 확정 |
| 전화상 안함 | lost | 번호 오류·연락 안 됨 |
| (상세 창 '이미 등록된 회원' ≥ 1) | enroll | 스니펫이 상태를 "등록"으로 바꿔 넘긴다 |

- 방문(visit)은 신규 회신에 따로 없다 → 현재는 consult 다음이 enroll. 
- **주의:** '이미 등록된 회원'은 이름·전화번호가 같은 회원이 있으면 1 — 원래 회원이 다시 지원해도 등록으로 잡힌다. 리포트 페르소나 caution 에 적는다.
- 신규 등록(`/admin/register`)은 회원 입력 양식, 멤버(`/admin/members`)는 카드 목록이라 광고명이 없다 → 광고별 등록은 위 상세 창으로만 알 수 있다.

## 일일 건수 스니펫 (일일 현황)
- `scripts/mkd/jeonsan-daily.js` 의 `__mkdDaily("YYYY-MM-DD")` — 같은 데이터 보드에서 그 날 유입경로별 **문의·등록 건수만** 센다(상세 창 안 염, NAME·전화번호 안 읽음). 코멘트는 `gads_`/`nad_`/`homepage` 토큰만 찾고 전문은 버린다. 밖으로 나가는 건 숫자와 토큰·유입경로 글자 일부뿐. 날짜 형식이 틀리면 던지지 않고 `{ error }` 를 돌려준다.
- **사전 조건**: 데이터 보드가 **1페이지**이고 날짜 D 가 든 달이어야 한다. D 가 지난달이면 데이터 보드 위쪽 `‹` 를 먼저 한 번 눌러 달을 바꾼다(스니펫은 `‹ ›` 를 누르지 않고 아래 숫자 버튼만 누른다).
- 세는 규칙
  - 문의 = 지원 시간이 D 인 행. 등록 = 상태가 "등록" 이고 마지막 업무 시간이 D 인 행. **미검증**: 데이터 보드 표에 "등록" 상태가 실제로 나오는지 확인하지 못했다 → 라이브 첫 실행에서 `statuses` 에 "등록" 이 있는지 본다. 없으면 `enrolls` 는 늘 0 이니 쓰지 않는다.
  - 등록은 지원한 날과 등록한 날이 다를 수 있어 D 의 **14일 전까지**(`backDays`) 행을 훑는다. 그보다 더 전에 지원한 사람이 D 에 등록하면 못 센다.
  - `bySource` 키(= `mkd_daily(jeonsan)` 의 unit) 순서: ① 코멘트의 토큰(소문자) — `gads_*`=구글, `nad_*`=네이버, `homepage`. 40자까지, 숫자 3자리 이상 덩어리가 있으면 그 앞까지만 쓰고 남는 게 없으면 `기타`(`gads_기타` 같은 값은 rows.mjs 가 거부). ② 광고명이 있고 `-` 가 아니면 `meta`(메타 리드폼). ③ 유입경로 글자 — 숫자 덩어리를 전부 `#` 로 가린 뒤 20자까지(`네이버 예약 0101234567` → `네이버 예약 #`). 비었거나 `-` 거나 결과가 `전체` 면 `기타`.
- 돌려주는 키

| 키 | 뜻 |
|---|---|
| `total` | D 의 문의 합 |
| `bySource` | `{ 키: { inquiries, enrolls } }` |
| `pages` | 훑은 쪽 수 |
| `scanned` | 지원 시간을 읽은 행 수(멈추게 한 오래된 행 포함) |
| `stoppedBy` | 끝난 이유. `cutoff` = 14일 전보다 오래된 행에 닿음(정상) · `lastPage` = 다음 숫자 버튼이 없음(정상) · `maxPages` = 쪽 수 상한(기본 12)에서 멈춤(불완전) · `stalled` = 버튼을 눌렀는데 5초 넘게 표가 안 바뀜(불완전, 같은 쪽을 다시 세지 않음) |
| `newest`, `oldest` | 읽은 첫 행·마지막 행의 지원 시간 날짜(YYYY-MM-DD) |
| `unparsed` | 표에 있는데 지원 시간 날짜를 못 읽은 행 수 |
| `missingCols` | 없는 열 — `코멘트`·`광고명`·`유입경로`·`마지막 업무 시간` 중 |
| `filterSet` | 상태 select 를 찾아 "전체"로 맞췄는지 |
| `statuses` | `{ 상태 글자: 행 수 }` — 읽은 모든 행. 숫자는 `#`, 12자까지. 표에 "등록" 이 나오는지 보는 용도 |
| `enrollsUnavailable` | 마지막 업무 시간 열이 없어 `enrolls` 를 못 센 경우 true(이때 enrolls 는 쓰지 않는다) |

- 오류 반환: 지원 시간 날짜를 하나도 못 읽으면(행은 있는데 `scanned` 0) `{ error: "지원 시간 형식을 못 읽었어요", … }`. 상태·지원 시간 열이 없으면 `{ error: "열 없음: …", headers }`(NAME·전화 열 이름은 뺀다).
- **호출한 쪽의 합격 검사**(스킬): `error` 없음 · `filterSet === true` · `scanned > 0` · `stoppedBy` 가 `"cutoff"` 또는 `"lastPage"` · `oldest <= D` 또는 `stoppedBy === "lastPage"` · `unparsed === 0`. 하나라도 어긋나면 그 지점 jeonsan 행은 숫자를 "적어도 이만큼"으로만 쓰도록 `partial`, `error` 거나 읽은 행이 없으면 `failed`. `missingCols` 에 코멘트·광고명·유입경로가 있으면 소스 구분이 뭉개지니 `partial`. `lastPage` 인데 `oldest` 가 D 보다 새로우면(이 달 표가 D 보다 늦게 시작) 달이 맞는지 한 번 더 본다 — 특히 `total` 0 일 때.
