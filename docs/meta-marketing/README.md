# 📣 메타 마케팅 (팔로플래너 "마케팅" 탭 + Claude 스킬 4개)

메타(인스타·페북) 데이터로 지점별 "실제 등록하는 사람"을 분석하고, 그들이 좋아할 광고 소재·피드·릴스를 만들어 오가닉으로 최대한 멀리 퍼지게 하는 시스템.
2026-10-24 맥미니 세션에서 설계(brainstorming). 구현은 아래 "만드는 순서"대로 단계별로.

## 한 줄 구조

**무거운 일은 Claude 스킬(엔진), 보고·승인·촬영 업로드는 팔로플래너 마케팅 탭(창구), 둘 사이는 Supabase.**

```
[데이터 입구]                     [Claude 스킬 = 엔진]             [플래너 마케팅 탭 = 창구]
메타 광고 CSV → API   ─┐
인스타·페북 인사이트   ─┼─▶ ① 분석 ──────────▶ 주간 리포트 · 페르소나 (지점별)
전산 리드→등록(브라우저)┘      │
벤치마크 계정·레퍼런스 URL ─▶ ③ 트렌드 ───────▶ 포맷 카드 · 촬영 가이드 · 콘티
                              ▼
                         ② 콘텐츠 ──────────▶ 광고 소재 · 피드 · 캐러셀 시안
                              ▼                      │
                         ④ 영상 ◀────────── 매니저 촬영 컷 업로드
                     (Higgsfield AI컷 + 자동 조립)    │
                              ▼                      ▼
                    완성 영상 / 캡컷 묶음 ──▶ 매니저 승인 ──▶ 예약 자동 게시(API)
```

## 확정된 결정 (사용자와 정함)

- **대상:** 팔로 학원 4개 지점, 지점별 인스타·페북·광고 계정. 전부 한 비즈니스 포트폴리오 안에 있음. 지점 정보는 `docs/blog-writer/README.md` 의 지점 표, 지점 프로필은 블로그 작성기 `blog_profiles` 를 같이 씀.
- **구 브랜드 "컬컴/CULCOM" 언급 금지** (블로그 작성기와 같은 절대 규칙). willycopyright 스킬의 카피 틀은 가져오되 브랜드명은 팔로.
- **목표:** 최종 = 상담 문의(→ 등록), 중간 지표 = 도달·저장·공유. 판단 핵심 지표는 **등록당 비용**(리드당 비용만 보면 착시).
- **알고리즘은 "세팅"이 아니라 신호 만들기:** 시청 유지율(첫 3초 훅), 저장·공유를 부르는 형식, 꾸준한 업로드, 지점 페르소나 활동 시간대에 게시.
- **데이터 입구 = CSV로 시작 → API로 전환.** 분석 로직은 같고 입구만 바뀐다.
  - 광고·인사이트 CSV: **대표가 매주 4개 지점 것을 한 번에** 올림 (API 전환 전까지).
  - 전산(branch.pallo.co.kr): 내보내기 없음 → **Claude가 브라우저로 읽음**(pallo-naver-booking-sync 와 같은 방식). 리드는 페북 잠재고객 광고 → 전산에 이름·번호·광고명, 이후 상담→방문→등록 진행 상태가 기록됨. **이름·번호는 읽지도 저장하지도 않음.** 광고명·지점·날짜·상태(+있으면 나이대·관심과목)만.
- **분석 주기:** 주간 리포트 매주 월요일 아침 자동 + 페르소나는 매달 갱신.
- **콘텐츠 1차 범위:** 리드 광고 소재 + 피드/캐러셀(**지점당 주 3개**) + 캡션·해시태그·업로드 시간. 릴스 대본은 ④에서, 스토리(투표·질문)는 나중에.
- **게시:** 피드·릴스는 **매니저가 자기 지점 것을 승인 → 예약 시간에 API 자동 게시.** 광고 소재는 자동 게시 안 함, 대표가 광고관리자에서 직접 올림.
- **점검기:** 승인 전에 금지 표현·가격 표기·얼굴 노출·컬컴 언급 등을 **경고로만** 띄움(막지 않음). 블로그 작성기 발행 전 점검기 재사용.
- **트렌드 소스:** 벤치마크 계정(10~15개, Claude가 후보 조사 → 대표가 선택) + 레퍼런스 URL 수집함 + 우리 계정 상위 릴스. 틱톡·쇼츠 음원은 참고용만. **원본 대사·영상·얼굴 복제 금지, 구조만.**
- **릴스:** 지점당 주 2개.
- **하이브리드 영상 역할 분담:** 우리가 찍는 것 = 강사·학생의 실제 얼굴·목소리, 실제 강의실. AI(Higgsfield) = 해외 상황극 배경·B-roll, 첫 1~3초 훅 비주얼, 편집·후반(컷·자막·음원·9:16). AI 인물 상대역·음성 복제/더빙은 테스트 후 결정.
- **최종 편집:** 기본 = 자동 조립 완성본. 중요한 영상(광고 메인·지점 대표)은 **캡컷으로 넘기기** = 번호 붙인 컷 + SRT 자막 + 콘티 시트 묶음. 캡컷 프로젝트 파일 직접 생성은 형식 비공개·암호화라 구현 때 실제 테스트 후 되면 추가.

## 구성 요소

### ① 분석 스킬
- **입력:** 광고(광고·소재별 노출·클릭·리드·리드당 비용, 연령·성별·지역·게재위치·시간대), 오가닉(게시물별 도달·3초 시청·평균 시청시간·저장·공유·댓글·프로필 방문), 전산(광고명·지점·날짜·상태).
- **출력(지점별, 플래너에 저장):**
  - 이번 주 판정: 계속 밀 소재 / 끌 소재(피로도·높은 등록당 비용) / 새로 테스트할 방향
  - 오가닉 상위·하위 게시물과 이유
  - 페르소나 카드(월간): 실제 등록자의 연령·관심과목·반응한 메시지·활동 시간대. 표본 적은 지점(구미)은 다른 지점 패턴을 빌리되 "빌린 패턴" 표시.

### ② 콘텐츠 스킬
- **입력:** 지점 페르소나, 이번 주 판정, 지점 프로필, 지점 사진 라이브러리(실사 우선 — 신뢰도).
- **출력:** 리드 광고 소재(기본문구·제목·설명·CTA, 페르소나별 3안 + 이미지), 피드/캐러셀 주 3개(표현 정리·꿀팁·후기 카드뉴스·상황별 회화 등 저장·공유형).
- **모든 게시물에:** 캡션, 해시태그, 추천 업로드 시간, **추적 코드**(DM 키워드 또는 지점별 링크 — 오가닉 문의 출처 추적용).
- 지난 게시물과 주제·문구 중복 회피.

### ③ 트렌드 스킬
- 매주 벤치마크 계정 최근 인기 릴스 + 수집함 + 우리 상위 릴스를 분석: 훅(첫 3초 말·화면), 컷 길이·템포, 자막 스타일, 음원, 구조(문제→해결, 상황극, 비포·애프터…), 길이.
- **출력 "이번 주 포맷 카드":** 원본에서 가져올 구조 → 팔로 버전 아이디어 → 지점 적용 예시.

### ④ 영상 스킬
1. 콘티: 포맷 카드 + 페르소나 → 컷 단위, 컷마다 `직접 촬영` / `AI 생성` 표시
2. 촬영 가이드(플래너): 컷별 무엇·대사·카메라 위치·세로·초 수·조명 팁·예시 이미지
3. 매니저가 콘티 칸마다 영상 업로드 (길이·방향 안 맞으면 즉시 경고)
4. AI 컷 생성(Higgsfield), 지점 톤에 색감 통일
5. 자동 조립: 컷 연결, 강사 음성 자동 자막, 음원·효과음, 9:16 → 완성본 / [캡컷으로 넘기기]
6. 매니저 승인 → 예약 자동 게시

### 플래너 마케팅 탭
리포트·페르소나 보기, 시안 확인·승인, 콘티·촬영 가이드 보고 컷 업로드, 레퍼런스 URL 수집함, 지점 사진 라이브러리, CSV 업로드(대표). 권한은 블로그 작성기와 같음: 매니저 = 자기 지점, 대표(role=admin) = 전체 + 사용량.

### Supabase
스킬이 결과를 쓰고 플래너가 읽는 공용 저장소. 촬영 컷·AI 컷·완성본은 Storage. 메타 토큰은 **Supabase secret**(채팅에 붙여넣지 않기). 예약 자동 게시는 Edge Function + 스케줄.

### 구현 위치 (0~1단계)
- 계산: `mk-core.js` (테스트 `node --test 'tests/*.test.mjs'`) · 화면: `marketing.js` / `marketing.css` · DB: `supabase/migrations/20261025120000_marketing.sql`
- 스킬: `~/.claude/skills/pallo-meta-analyze/SKILL.md` → 스크립트 `scripts/mk/*.mjs` (서비스 키: `~/.config/pallo/marketing.env`), 전산 읽기 스니펫 `scripts/mk/jeonsan-extract.js`
- 전산 화면 구조: `docs/meta-marketing/jeonsan-leads.md`
- 광고 계정: 실제 광고는 **"팔로 대구 동성로점" 광고 계정(3542016502769477)** 하나에서 4개 지점이 같이 돈다. 광고관리자 열 구성 **"팔로 마케팅 분석용"**(캠페인 이름 포함)으로 내보낸다. 금액 USD.

| 단계 | 내용 | 메타 API 필요 |
|---|---|---|
| 0 | 마케팅 탭 뼈대, Supabase 테이블·Storage, 지점 프로필 연결 | 아니요 |
| 1 | ① 분석: CSV 업로드 + 전산 읽기 → 첫 주간 리포트 | 아니요 |
| 2 | ② 콘텐츠: 광고 소재 + 피드 주 3개, 점검기·승인, 수동 다운로드 | 아니요 |
| 3 | ③ 트렌드: 벤치마크 계정 선정 + 포맷 카드 | 아니요 |
| 4 | ④ 영상: 콘티 → 촬영 업로드 → AI 컷 → 자동 조립 → 캡컷 묶음 | 아니요 |

메타 준비가 일찍 끝나면 5단계를 앞당긴다. 각 단계는 실제로 쓰면서 확인한 뒤 다음으로.

## 메타 API 준비 (대표가 직접)

1. 비즈니스 포트폴리오 — 4개 지점 자산 확인 (완료: 전부 한 포트폴리오)
2. 비즈니스 인증 (사업자등록증, 며칠 걸림 — 먼저 시작)
3. developers.facebook.com 에서 "비즈니스" 앱 → 포트폴리오 연결 → Marketing API + Instagram API(Facebook 로그인) 추가
4. 시스템 사용자 생성 → 4개 지점 자산 할당 → 토큰 권한:
   `ads_read`, `read_insights`, `business_management`, `pages_show_list`, `pages_read_engagement`, `instagram_basic`, `instagram_manage_insights`, `instagram_manage_comments`, **`instagram_content_publish`, `pages_manage_posts`**(자동 게시용)
5. 토큰은 Supabase secret 으로

## 예외 처리

- CSV 안 올린 주 → 오가닉·전산만으로 리포트, 상단에 "광고 데이터 없음".
- 전산 로그인 만료·화면 변경 → "등록 데이터 누락" 표시 + 대표에게 알림. 리드당 비용으로 몰래 대체하지 않음.
- 표본 적음 → 결론 대신 "판단 보류 (표본 n건)".
- AI 컷 실패·이상 → 재생성/다른 후보 → 그래도 안 되면 그 칸을 "직접 촬영"으로 바꾸자고 제안.
- 자동 게시 실패 → 플래너에 실패 표시 + 매니저 알림 + 수동 다운로드 가능.
- 비용 → Higgsfield 크레딧·Claude API 사용량 지점별 기록, 대표가 상한 설정.

## 검증

- 1단계: 첫 리포트를 대표가 아는 실제 상황("이 소재가 등록 잘 됐다")과 대조.
- 2단계~: 점검기 통과 여부 + 2주 실게시 후 저장·공유를 이전과 비교.
- 4단계: 테스트 영상 1편을 끝까지 만들고, 촬영 가이드가 이해되는지 실제 매니저 1명과 확인.
